# Лабораторная работа №3. Распределенное умножение квадратных матриц (MPI)

## 1. Описание алгоритма

### 1.1 Распараллеливание с помощью MPI и порядок обхода i-k-j

В отличие от последовательной реализации, технология **MPI (Message Passing Interface)** использует модель распределенной памяти (Distributed Memory). Запускаются изолированные процессы, которые обмениваются данными посредством явной передачи сообщений.

В данной работе реализована топология **"Начальник - Подчиненные" (Master-Worker)**:
1. Процесс с рангом `0` считывает исходные матрицы $A$ и $B$ из файлов.
2. Матрица $B$ рассылается всем процессам целиком с помощью функции `MPI_Bcast`.
3. Матрица $A$ разрезается на горизонтальные полосы и распределяется между процессами функцией `MPI_Scatterv`.
4. Каждый процесс выполняет перемножение своей локальной части $A$ на матрицу $B$.
5. Локальные матрицы $C$ отправляются обратно нулевому процессу и склеиваются с помощью `MPI_Gatherv`.

Внутри локальных вычислений каждого процесса сохранен оптимизированный порядок обхода циклов **i-k-j**:

```cpp
for (int i = 0; i < local_rows; ++i) {
    for (int k = 0; k < n; ++k) {
        double a_ik = local_A[i * n + k];
        for (int j = 0; j < n; ++j) {
            local_C[i * n + j] += a_ik * B[k * n + j];
        }
    }
}
```

### 1.2 Хранение матриц

Матрицы хранятся в виде одномерных массивов `(std::vector)` с линейной индексацией `[i * n + j]`. Для MPI непрерывность блока памяти критически важна: функции пересылки данных (MPI_Bcast, MPI_Scatterv) могут работать только с единым непрерывным участком памяти.

### 1.3 Вычислительная сложность

* **Количество математических операций**: **2N³** (распределены поровну между T процессами).

* **Сложность по памяти:** **(T + 2) × N²** элементов типа `double`. Ввиду распределенной памяти, матрица B дублируется T раз (у каждого процесса своя полная копия). Это приводит к кратному росту потребления ОЗУ.

## 5. Анализ результатов

### 5.1 Потребление оперативной памяти и накладные расходы

В отличие от Л/Р №1 и №2, где потребление памяти было фиксированным, в MPI-программе оно растет линейно с количеством запущенных процессов. Это связано с тем, что технология MPI использует изолированную память для каждого процесса.

### 5.2 Производительность и влияние кэш-памяти

График производительности (GFLOP/s) наглядно демонстрирует влияние иерархии памяти:
1. **Пик производительности**: Достигается при N=400 (до **35.86 GFLOP/s**). Здесь проявляется сильная сторона изолированных MPI-процессов — они не затирают кэш L1/L2 друг друга, и локальные куски матриц обрабатываются максимально быстро.
2. **Падение производительности**: При N=800 и выше матрицы перестают помещаться в кэш. Возникают множественные кэш-промахи, и производительность 12 процессов падает с 35.8 до 14.9 GFLOP/s.

### 5.3 Временная сложность и время выполнения

Экспериментальные данные полностью подтверждают теоретическую асимптотическую сложность алгоритма умножения матриц — **O(N³)**. На совмещенном графике времени выполнения видно, что для любой конфигурации процессов кривая представляет собой классическую кубическую параболу.

Применение MPI позволяет существенно сократить фактическое время вычислений: для матрицы N=2000 базовое время на 1 процессе составило **4.50 сек**, а при использовании 12 процессов оно сократилось до **1.06 сек** (ускорение ~4.2x). Стоит отметить, что ускорение не является идеально линейным из-за закона Амдала: значительная часть времени уходит на последовательные операции — чтение/запись файлов процессом с рангом `0` и межузловую коммуникацию (`MPI_Scatterv`, `MPI_Gatherv`).

## 6. Выводы

1. Разработана и успешно протестирована MPI-программа для распределенного перемножения матриц на языке C++.
2. Доказано, что в рамках одного локального компьютера MPI проигрывает технологиям разделяемой памяти (OpenMP) на больших объемах данных из-за высоких накладных расходов на дублирование и пересылку сообщений.
3. Выявлено узкое место архитектуры: MPI обладает кратно более высокой потребностью в оперативной памяти (дублирование O(N²)).
