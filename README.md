# Лабораторная работа №4. Параллельное умножение квадратных матриц на GPU (CUDA)

## 1. Описание алгоритма

### 1.1 Распараллеливание с помощью NVIDIA CUDA

В отличие от центрального процессора (CPU), который использует несколько мощных ядер (например, 12 потоков в OpenMP), графический ускоритель (GPU) построен на архитектуре **SIMT** (Single Instruction, Multiple Threads) и содержит тысячи вычислительных CUDA-ядер. 

При переносе алгоритма на видеокарту парадигма программирования меняется:
* На CPU мы использовали циклы `for` для обхода строк и столбцов.
* На GPU внешние циклы `i` и `j` полностью убираются. Вместо этого запускается "Сетка" (Grid) из миллионов независимых "Потоков" (Threads). Каждый поток вычисляет строго один элемент итоговой матрицы C. Позиция потока определяется через его встроенные аппаратные координаты: `threadIdx`, `blockDim` и `blockIdx`.

```cpp
__global__ void matrixMulKernel(const double* A, const double* B, double* C, int n) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;

    if (row < n && col < n) {
        double sum = 0.0;
        for (int k = 0; k < n; ++k) {
            sum += A[row * n + k] * B[k * n + col];
        }
        C[row * n + col] = sum;
    }
}
```

### 1.2 Хранение матриц и работа с памятью
Память компьютера (Host) и память видеокарты (Device) физически разделены. Прежде чем начать вычисления, необходимо:

1. Выделить память в VRAM видеокарты (функция `cudaMalloc`).

2. Скопировать исходные матрицы A и B из ОЗУ в видеопамять по шине PCI-Express ('cudaMemcpyHostToDevice').

3. После вычислений скопировать результат C обратно в ОЗУ ('cudaMemcpyDeviceToHost').

### 1.3 Вычислительная сложность

* **Количество математических операций**: **2N³** (N³ умножений и N³ сложений).
* **Сложность по памяти**: **3N²** элементов типа 'double'. Дополнительно возникает накладной расход по времени на копирование матриц между RAM и VRAM.

## 5. Анализ результатов

### 5.1 Временная сложность

Экспериментальные данные подтверждают теоретическую асимптотическую сложность алгоритма O(N³). На графике зависимости времени выполнения от размера матрицы (N) наблюдается классическая кривая кубической параболы. Данная зависимость сохраняется вне зависимости от выбранного размера конфигурации блоков.

### 5.2 Производительность

Анализ производительности выявил существенное превосходство графического ускорителя (RTX 4060 Ti) над центральным процессором в задачах с массовым параллелизмом данных.
Для максимальной матрицы N=2000 время выполнения на GPU составило всего **0.05 сек**, а пиковая производительность достигла **321 GFLOP/s**. Для сравнения, аналогичное перемножение в Л/Р №2 (OpenMP на 12 потоках CPU) занимало **0.54 сек** (макс. 32 GFLOP/s). Видеокарта выполнила задачу в 10 раз быстрее многоядерного процессора, что доказывает высокую эффективность архитектуры SIMT.

### 5.3 Влияние конфигурации сетки блоков

Графики производительности для размерностей блоков 8x8, 16x16 и 32x32 показывают практически идентичные результаты. Слияние графиков объясняется следующими аппаратными факторами:

1. Выравнивание по варпам (Warp Alignment): Планировщик видеокарты выполняет потоки фиксированными группами по 32 потока (варпами). Поскольку площади всех протестированных блоков (64, 256, 1024 потока) делятся на 32 без остатка, простоя CUDA-ядер внутри варпов не возникает.
2. Ограничение пропускной способности видеопамяти (Global Memory Bound): В реализованном алгоритме каждый поток обращается за данными напрямую в глобальную память видеокарты (VRAM). Вычислительные блоки GPU обрабатывают данные быстрее, чем шина видеопамяти успевает их поставлять, в результате чего достигается физический предел пропускной способности, нивелирующий разницу между конфигурациями блоков.

3. Продемонстрирована высокая эффективность графических ускорителей: производительность GPU на порядок превысила аналогичные показатели CPU при работе с большими матрицами.
